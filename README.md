# Ignition Firmware Flasher — Server

Сервер управления прошивками и флешерами системы зажигания Ignition.
Хранит прошивки в зашифрованном виде (AES-128-CTR), проверяет их целостность
(HMAC-SHA256), авторизует пользователей через JWT и раздаёт файлы по ролям.

---

## Требования

- **Go 1.25+** — для локального запуска (`go run .`).
- **Docker + Docker Compose** — для запуска в контейнере.

---

## Настройка `.env`

Конфигурация хранится в файле `.env` (он в `.gitignore` / `.dockerignore` и
не должен попадать в git). Создайте его из шаблона:

```bash
cp .env_example .env
```

Основные переменные:

| Переменная       | Описание                                                                 |
|------------------|--------------------------------------------------------------------------|
| `LISTEN_ADDR`    | Адрес и порт HTTP-сервера, по умолчанию `0.0.0.0:8200`.                 |
| `FIRMWARES_DIR`  | Каталог для загруженных прошивок, по умолчанию `./firmwares`.           |
| `FLASHERS_DIR`   | Каталог для загруженных флешеров, по умолчанию `./flashers`.            |
| `DB_DIR`         | Каталог БД SQLite, по умолчанию `./` (файл `database.sqlite3`).         |
| `ADMIN_TOKEN`    | Необязательный токен для устаревших admin-запросов.                     |
| `JWT_SECRET`     | **Обязателен** — hex-секрет для подписи и проверки JWT.                 |
| `AES_KEY`        | **Обязателен** — 16 байт в hex (32 символа), AES-128 для шифрования прошивок. |
| `HMAC_KEY`       | **Обязателен** — 32 байта в hex (64 символа), HMAC-SHA256 для контроля целостности. |

---

## Генерация секретов

```bash
go run . -init-secrets
```

Команда сгенерирует отсутствующие `JWT_SECRET`, `AES_KEY` и `HMAC_KEY` и допишет
их в `.env`. Повторный запуск ничего не перезаписывает — если секреты уже есть,
она сообщит, что делать нечего.

---

## Создание администратора

```bash
go run . -create-admin
```

Интерактивно запросит имя пользователя и пароль (пароль вводится скрытно) и
создаст первого администратора с ролью `admin`. Роль `admin` нельзя назначить
через публичный API. Если администратор уже существует, команда откажет.

---

## Локальный запуск

```bash
go run .
```

Сервер будет доступен по адресу **http://localhost:8200**.

Также можно собрать исполняемый файл через `run.bat` (Windows) или
`go build -o firmware-server.exe` / `go build -o server`.

---

## Запуск через Docker Compose

Из директории `server/`:

```bash
docker compose build
docker compose run --rm server -init-secrets
docker compose run --rm server -create-admin
docker compose up -d
```

> **Примечание.** `docker compose` читает секреты из `.env` на хосте
> (`env_file: .env`). Если вы используете только Docker, проще сначала
> сгенерировать секреты локально (`go run . -init-secrets`), а затем выполнить
> команды выше — так `.env` будет содержать рабочие ключи для контейнера.

После запуска сервер доступен на **http://localhost:8200**.

## Volumes

Данные приложения хранятся в именованном томе `ignition-flasher-data`, который
смонтирован в каталог `/app/data` внутри контейнера:

- `/app/data/db` — БД SQLite (`database.sqlite3`);
- `/app/data/firmwares` — загруженные прошивки;
- `/app/data/flashers` — загруженные флешеры.

Так как данные лежат в volume, они **сохраняются после пересоздания или удаления
контейнера**.

## Структура проекта

```
server/
├── main.go               # Точка входа: загрузка конфигурации, шаблоны, маршруты
├── config/               # Загрузка конфигурации из .env и генерация секретов
├── db/                   # SQLite: сущности, репозиторий, схема
├── handlers/             # HTTP-обработчики (auth, users, firmware, flasher)
├── middleware/           # Middleware: JWT-аутентификация, проверка ролей
├── services/             # Бизнес-логика (auth, firmware, flasher, encrypting)
├── ui/                   # Frontend: HTML-шаблоны (templates/ и pages/), CSS, JS
├── firmwares/            # Каталог загруженных прошивок (локально)
├── flashers/             # Каталог загруженных флешеров (локально)
├── database.sqlite3      # БД SQLite (локально)
├── Dockerfile            # Multi-stage сборка образа
├── docker-compose.yml    # Production-конфигурация Docker Compose
├── .env_example          # Шаблон конфигурации
└── go.mod / go.sum       # Зависимости и модуль Go
```
